# What the song taught the tool

**Why this project exists.** The goal is the MCP, recipes and skills: a connector that can remix any song (and mix, gain stage, master) with the user approving by ear. "Friends in Low Places" is the test bed. A fix that only improves this song's project file is not progress; it is progress only when it lands as a module, a recipe, a skill rule, a measure or a test that the next song gets for free. Rule for every session: after any change to the song, ask "where does the general version of this live?" and either write it there or log it below as song specific.

Each row: what happened, what the general version is, and where it stands. Update this file whenever a listening note or a hand fix arrives.

## What is still song specific (do not mistake for the product)

`remixplan.py`'s built-in values (the same data now also lives in `plans/friends_in_low_places.json`, which a build can load instead), and every number in `SERUM_DB`. Song analysis (`songanalysis.py`, module `build_song_plan`) now produces a plan from word times, drum hits and bass roots; it is proven only on this song until a second one is run. The product needs these produced from analysis of whatever song is given (`STEM_REMIX_PIPELINE.md`, "Generalising to a second song").

## Order of work that serves the tool (status 2026-10-24: items 1 to 5 done in code and tests; item 6 needs the person's second song)

1. Module `diff_flp_projects` (read only): channel, sample, preset, mixer, note and playlist differences between two projects. Every user hand fix then becomes a report the recipes can learn from.
2. Module `measure_part_timing` (read only, V3) and use it on the chops once the user names the ones that sound off.
3. Per-part gain staging loop from solo renders, replacing the hand numbers.
4. Write items 2, 3 and 6 into `sound-design-recipes`, `gain-staging` and `editable-first`.
5. Turn the remix build into registered modules and a skill an agent can call without a person running scripts.
6. Second song, end to end, as the proof of generalisation. Master pass when the user supplies a reference track.
